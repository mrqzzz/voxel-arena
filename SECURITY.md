# Security Policy

Thank you for taking the time to report a security vulnerability in Voxel Arena. We take the security of this project seriously and appreciate your efforts to responsibly disclose any issues you find.

## Supported Versions

The following table lists the versions of Voxel Arena that are currently being supported with security updates. Please ensure you are reporting a vulnerability present in a supported version.

| Version | Supported          |
| ------- | ------------------ |
| Main branch | :white_check_mark: |
| 1.x.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

*(Note for the maintainer: Update the version numbers in this table to reflect your actual release strategy.)*

## Reporting a Vulnerability

**Do not open a public GitHub issue to report a security vulnerability.** Public disclosure before a fix is available puts the project and its users at risk.

To report a security vulnerability, please choose one of the following methods:

1. **Email:** Send an email directly to `[mrqzzz@yahoo.it]`.
2. **GitHub Private Vulnerability Reporting:** Navigate to the **Security** tab of the `mrqzzz/voxel-arena` repository, click on **Advisories**, and use the **Report a vulnerability** button (if enabled).

### Information to Include

To help triage and resolve the issue quickly, please include the following details in your report:

*   **Vulnerability Type:** (e.g., Cross-Site Scripting, Remote Code Execution, Denial of Service).
*   **Affected Components:** Specify the files, modules, or features involved.
*   **Steps to Reproduce:** Provide clear, step-by-step instructions to reproduce the vulnerability.
*   **Proof of Concept (PoC):** Include any scripts, code snippets, or payloads that demonstrate the exploit.
*   **Potential Impact:** Describe what an attacker could achieve by exploiting this vulnerability.
*   **Suggested Mitigation:** If you have a proposed fix, please include it.

### Triage and Resolution Process

1.  **Acknowledgment:** Receipt of your report will be acknowledged within 48 hours.
2.  **Triage:** The issue will be investigated to confirm whether it is a valid vulnerability within 5 business days.
3.  **Remediation:** If the vulnerability is valid, a fix will be developed. You may be contacted for further clarification or to test the patch privately.
4.  **Disclosure:** Once the fix is released, the vulnerability will be publicly disclosed, and your contribution will be acknowledged (unless you request to remain anonymous).
